# Cat Loader — ChatGPT 연결과 공통 내비게이션 재설계

작성: 2026-11-11. 상태: Cat Loader 0.4.3 실제 앱 적용·로컬 검증 완료. 실계정·물리 DPI 전환·사용자 UX 검토는 남아 있음. [구현 검증 기록](../../reviews/2026-11-11-chatgpt-redesign-implementation.md).

## 범위와 이전 설계의 실패

사용자가 선택한 범위는 **ChatGPT 연결 화면 전체와 공통 내비게이션**이다. 로컬 모델 화면 내부, 모델 6개, 모델 추가·다운로드·프롬프트 편집 흐름은 변경 대상이 아니다.

기존 설계는 계정·서버·연결값·사용량·진단을 긴 세로 양식으로 쌓았다. 로그아웃은 접힌 진단 안에 있었고, 로그인 상태와 API 준비 상태를 한 문구로 표시했다. 로그인 전에도 의미 없는 키 마스킹과 복사 항목을 보여줬다. `로그인`, `연결 시작`, `작업 취소`, `연결 중지`가 멀리 떨어진 같은 버튼 자리에서 바뀌었다. 탐색 버튼과 실행 버튼의 모양도 같았다.

이전 코드 검사 결과가 이런 UX를 승인한 근거가 될 수 없다. 이전 설계의 ChatGPT 화면 구성과 단일 주 버튼 규칙은 이 제안으로 대체한다. 기존 저장소·프로세스 안전성·기능 독립성 요구는 유지한다.

## 제품이 전달해야 할 네 가지

1. 이 기능은 ChatGPT 계정을 다른 앱에서 사용하도록 연결한다. 인터넷이 필요하고 해당 계정의 사용 한도를 쓴다.
2. **로그인**은 이 PC에 계정을 연결한다. **서버 켜기**는 다른 앱의 요청을 받기 시작한다.
3. **서버 끄기**는 로그인 정보를 유지한다. **로그아웃**은 서버를 끄고 이 PC의 로그인을 지운다.
4. 다른 앱에는 표시된 API 주소·API 키·모델 이름을 입력한다. 로컬 모델용 연결값과 혼합하지 않는다.

## 선택한 화면 구조

밝은 Windows 유틸리티의 녹색과 기본 글꼴을 유지한다. 장식 대신 정렬·텍스트 크기·영역의 역할·동작 위치로 구분한다.

```text
Cat Loader       로컬 모델   ChatGPT 연결                    설정
                             ━━━━━━━━━━

ChatGPT 연결                                            사용 방법
ChatGPT 계정으로 다른 앱의 AI 기능을 사용합니다.

┌ ChatGPT 계정 ─────────┐    ┌ API 서버 ──────────────────────┐
│ 계정 상태 / 이메일    │    │ 서버 상태             서버 켜기│
│ 로그인 또는 로그아웃  │    ├───────────────────────────────┤
│                      │    │ 로그인 전: 이용 순서            │
├ 계정 사용량 ─────────┤    │ 서버 꺼짐: 다음 행동            │
│ 조회 / 한도 / 갱신    │    │ 서버 켜짐: 주소·키·모델과 복사   │
└──────────────────────┘    └───────────────────────────────┘
                            인터넷·계정 한도 안내    연결 진단

로컬 모델 · 중지   |   ChatGPT · 서버 실행 중 [서버 끄기]
```

- 왼쪽은 **누구의 계정인지와 계정 관리**를 담당한다. 로그아웃은 이메일 근처에 노출한다.
- 오른쪽은 **다른 앱의 요청을 받는 서버와 연결 설정**을 담당한다. 서버 켜기·끄기는 서버 제목 옆에 고정한다.
- 초기 화면의 우측 설명을 연결 완료 후의 실제 연결값으로 바꾼다. 텅 빈 입력칸이나 동작하지 않는 복사 버튼을 미리 늘어놓지 않는다.
- 계정과 서버를 두 영역으로 나누되 내부에 작은 카드들을 반복해서 넣지 않는다.
- 상단은 테두리 버튼 세 개 대신 텍스트 탐색 두 개와 선택 밑줄이다. 설정은 오른쪽의 아이콘+텍스트 동작이다.
- 상단 탐색은 화면만 이동한다. 로그인·다운로드·서버 시작·중지는 발생하지 않는다.
- 공통 하단에는 두 기능의 상태와 실행 중인 기능별 중지/취소를 제공한다. 화면을 바꿔도 켜진 서버를 숨기지 않는다.

세로 양식에서 로그아웃만 밖으로 옮기는 안은 문제의 정보 구조를 유지하므로 채택하지 않는다. 단계별 마법사로 모든 화면을 나누는 안도 재사용할 때 서버와 계정을 함께 확인하기 어려워 채택하지 않는다. 첫 사용 안내는 같은 서버 영역 안에서 제공한다.

## 상태와 동작

| 상태 | 계정 영역 | 서버 영역 | 다음 행동과 결과 |
|---|---|---|---|
| 처음 사용 | 계정 연결 설명, **ChatGPT 로그인** | 로그인 필요, 로그인→서버 켜기→연결값 입력 안내 | 로그인 클릭 시 필요한 엔진 준비 후 브라우저 인증 |
| 다운로드 | 실제 진행량·진행 단계, **다운로드 취소** | 로그인 필요 | 완료 시 브라우저; 실패 시 원인과 다시 시도 |
| 브라우저 인증 대기 | **로그인 페이지 다시 열기**, **로그인 취소** | 로그인 필요 | 같은 인증 세션 재사용. 새 로그인 중복 생성 금지 |
| 로그인 완료 / 저장된 계정 | 이메일·플랜, **로그아웃** | **꺼짐**, **서버 켜기** | 로그인 성공만으로 API 서버를 켜지 않음 |
| 서버 시작 중 | 저장된 계정, 중복 로그아웃 비활성 | 실제 단계, **시작 취소** | 서버·계정·기본 모델 확인 후 실행 중으로 전환 |
| 서버 실행 중 | 계정, **로그아웃**, 사용량 조회 | **실행 중**, **서버 끄기**, 연결값과 복사 | 새 요청을 받을 수 있음을 표시. 실제 추론 성공과 구분 |
| 사용량 조회 중 | 조회 중, **조회 취소** | 연결값과 **서버 끄기** 유지 | 조회 실패는 사용량 영역에만 표시 |
| 서버 꺼짐 | 계정과 로그아웃 유지 | **꺼짐**, **서버 켜기**, 로그인 유지 안내 | 재로그인 없이 시작 |
| 로그아웃 확인 | 계정 식별자와 영향 안내 | 기존 상태 유지 | 취소는 아무 변화 없음. 확인 시 서버 정리 후 로그인 삭제 |
| 중지/로그아웃 정리 중 | 완료로 표시하지 않음 | 중지 중; 중복 명령 비활성 | 정리 실패 시 남은 상태와 재시도 안내 |
| 포트 충돌 | 저장된 계정 유지 | 사용 중인 실제 포트, 복구 행동, **다시 시작** | 자동으로 다른 공개 API 주소로 바꾸지 않음 |
| 계정 읽기 불가 / 여러 계정 | 확인 필요, **상태 다시 확인**, **저장 폴더 열기** | 서버 시작 불가 이유 | 파일 자동 삭제·임의 계정 선택 금지 |
| 저장된 인증 만료 | 계정 확인 필요 | 요청 실패 원인과 **로그아웃 후 다시 로그인** 안내 | 사용자의 확인 없이 저장 로그인 삭제 금지 |
| 브라우저 열기 실패 / 인증 거절 / 시간 초과 | 각 원인과 재시도 버튼 | 서버 꺼짐 | 토큰·인증 URL의 비밀값을 오류에 노출하지 않음 |

로그인 후 이메일이나 플랜을 얻지 못하면 `저장된 로그인`을 표시한다. 빈 줄·가짜 이메일·추정한 플랜을 넣지 않는다. 저장된 자격 증명과 서버가 실제로 사용할 수 있는 인증은 별개의 사실이다.

## 문구와 버튼 계약

| 위치 | 문구 | 실제 의미 |
|---|---|---|
| 기능 제목 | ChatGPT 연결 | 고정된 탐색 이름 |
| 제목 아래 | ChatGPT 계정으로 다른 앱의 AI 기능을 사용합니다. | 기능의 목적 |
| 계정 주 동작 | ChatGPT 로그인 | 필요한 연결 프로그램 준비 + 브라우저 인증 + 계정 저장 |
| 저장된 계정 | 로그아웃 | 확인 후 이 PC 로그인 삭제; 필요하면 ChatGPT 서버 중지 |
| API 서버 주 동작 | 서버 켜기 / 서버 끄기 | 해당 영역의 API 서버에만 적용 |
| 계정 설명 | 서버를 꺼도 로그인은 유지됩니다. 계정을 바꾸려면 먼저 로그아웃하세요. | 중지와 로그아웃의 차이 |
| 연결값 설명 | 제공자에서 OpenAI 호환을 선택한 뒤 아래 값을 입력합니다. | 값을 어디에 넣을지 설명 |
| 조회 전 | 서버를 켜면 사용량을 조회할 수 있습니다. | 비활성 이유를 화면에 제공 |
| 진단 | 모델 목록 다시 확인 / 실제 요청으로 테스트 | 조회와 사용량을 쓰는 추론을 구분 |
| 실행 안내 | 인터넷 연결 필요 · ChatGPT 계정의 사용 한도 적용 | 실행 위치와 비용 자원의 구분 |

`실행`, `연결`, `확인`, `작업 취소`처럼 대상이 불명확한 단독 동사는 주 동작 이름으로 쓰지 않는다. 계정 동작과 서버 동작이 하나의 버튼에 번갈아 들어가지 않는다. 녹색 채움은 현재 필요한 시작 동작에 사용하고, 일반 복사·로그아웃·중지는 보통 버튼이다. 로그아웃 확인창의 최종 버튼만 위험색을 사용한다.

복사 대상은 `API 주소`, `API 키`, `모델 이름` 세 개다. 읽기 전용 텍스트로 표시하고 각 복사 버튼의 접근성 이름에 대상을 포함한다. API 키는 기본 마스킹, 표시/숨기기 제공, 화면 이동·트레이 숨김 시 다시 가린다. 복사 완료는 해당 버튼 또는 항목 근처에 짧게 표시한다. 전체 복사에는 로컬 API 키만 포함하며 OAuth 자격 증명을 포함하지 않는다.

## 사용량과 진단

- 넓은 창: 계정 아래에 사용량을 둔다. 조회 전에는 안내와 조회 버튼만 표시한다.
- 좁은 창: 계정 옆 `사용량` 버튼으로 별도 보기. 로그아웃과 서버 주 동작을 밀어내지 않는다.
- 서비스가 제공한 한도 기간, 사용 비율, 초기화 시각, 조회 시각을 표시한다. 숫자가 없으면 `정보 없음`으로 표시하고 0%로 꾸미지 않는다.
- 정지 후 이전 조회를 보여주면 `마지막 조회`임을 명시한다. 서버가 꺼져 있는 동안 새로고침은 비활성화한다.
- `연결 진단`은 별도 대화상자다. 계정 관리 항목은 넣지 않는다. 모델 확인과 실제 요청 테스트를 분리하며 실제 요청 앞에 사용량 반영 안내를 둔다.
- 진단 실패가 정상 서버·복사·중지 기능을 사라지게 해서는 안 된다. 실제 추론을 하지 않은 서버 시작을 `연결 테스트 성공`으로 표시하지 않는다.

Tab 순서는 상단 탐색 → 계정 동작 → 서버 동작 → 연결값 복사 → 진단 → 하단 상태 동작이다. 대화상자는 포커스를 가두고 Escape로 취소/닫기, 닫은 뒤 원래 동작으로 돌려준다. 상태 전환으로 기존 버튼이 사라지면 다음 관련 동작에 포커스를 옮긴다. 마우스가 없어도 같은 일을 할 수 있어야 한다.

최소 크기의 첫 뷰포트에서 해당 상태의 로그인/로그아웃과 서버 주 동작이 보여야 한다. 큰 글씨와 긴 번역 때문에 본문이 길어지면 스크롤하며, 공통 하단의 서버 중지·준비 취소는 남긴다. 계정과 서버에 별도 세로 스크롤을 만들지 않는다.

## 구현 시 반드시 달라져야 하는 부분

현재 `AccountConnection.LoginAsync`는 인증 후 모델을 조회하고 API를 준비 상태로 만든다. 이 동작을 그대로 둔 채 버튼만 나누면 새 설계와 맞지 않는다.

1. `AccountConnectionView`의 긴 단일 스택과 하단 공용 주 버튼을 계정/서버 두 영역으로 교체한다. 두 영역의 상태는 별도로 표현한다.
2. `AccountConnectionViewModel`에 로그인·로그아웃·서버 켜기·서버 끄기·각 취소 명령을 명시적으로 둔다. 공통 상태 알림과 기존 취소/세대 보호를 재사용하되 명령 가능 조건을 분리한다.
3. 인증만 수행하는 수명을 별도로 구현한다. 인증에 필요한 보조 엔진은 잠시 실행할 수 있지만, 사용자에게 제공하는 8319 서버는 로그인 완료만으로 실행 중이 되지 않는다. 인증 보조 프로세스는 공개 서비스 포트와 분리된 loopback 임시 포트를 쓰고 완료/취소/실패 후 회수한다. 포트 확보 경쟁·정리 실패도 검사한다. 기존 계정 저장소와 로컬 키는 유지한다.
4. `ConnectAsync`는 저장된 계정으로 명시적 서버 시작을 담당한다. 기본 모델 확인에 실패하면 계정은 보존하고 서버 실패로 표시한다.
5. `LoaderWindow`의 공통 탐색을 변경하되 로컬 모델 자식 화면은 유지한다. 기존 백그라운드 작업·트레이·완전 종료 기능도 두 서비스의 실제 상태로 동작해야 한다.
6. 17개 언어를 함께 갱신한다. 영어 fallback으로만 통과시키지 않고 긴 번역의 버튼과 핵심 설명도 확인한다.

HTML은 시안 도구이며 실제 앱에 WebView나 웹 런타임을 추가하라는 요구가 아니다. 네이티브 WinForms 레이아웃과 컨트롤을 유지한다. 데이터 경로·암호화 형식·다운로드 캐시·로컬 6개 모델·두 API 주소는 이 작업에서 바꾸지 않는다.

## 검증과 완료 조건

| 검사 | 합격 기준 |
|---|---|
| 첫 사용 | 계정 없이 열어도 자동 다운로드/로그인/서버 실행 없음. 로그인 버튼과 이용 순서가 보임 |
| 실제 다운로드 | 빈 임시 저장소에서 버튼으로 엔진 준비 시작, 진행·취소·실패를 확인 |
| 로그인 수명 | 브라우저 열기, 같은 세션 재열기, 취소, 거절, 시간 초과, 성공을 각각 검사 |
| 로그인 성공 | 계정 저장 표시, 로그아웃 노출, 사용자 API 서버는 꺼짐 |
| 서버 켜기 | 별도 클릭 후 계정·모델 검증 완료 시에만 연결값 노출 |
| 중지 / 로그아웃 | 중지는 로그인 유지. 로그아웃 취소는 상태 유지. 확인은 서버 정리 후 로컬 로그인 제거 |
| 계정 교체 | 기존 계정을 확인하고 로그아웃한 뒤 새 계정 로그인. 기존 로컬 모델 실행에 영향 없음 |
| 실제 연결 | 다른 클라이언트의 모델 조회와 실제 요청 성공을 별도로 검증. OAuth/추론 미실행은 미검증으로 표시 |

| 기능 전환 | 서버 유지, 키 다시 마스킹, 다른 기능의 실행 상태와 중지/취소 접근 가능 |
| 오류 | 포트 충돌·중복 실행·읽기 불가·인증 만료·모델 없음·정리 실패에서 원인과 다음 행동 유지 |
| 사용자 이해 | 별도 설명 없이 로그인, 서버 시작, 복사, 중지, 로그아웃을 구분해 수행할 수 있는지 사용자 검토 |

자동 테스트 통과, 시안의 시각 검토, 실제 OAuth/요청 검증, 사용자의 UX 판단을 별도로 보고한다. 하나가 통과했다고 나머지를 통과 처리하지 않는다.

- Microsoft의 [타이포그래피 지침](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography)은 텍스트 위계와 논리 크기 기반 배율을 설명한다. 이 앱에서는 사용자 피드백을 반영해 일반 본문 16 px, 보조 14 px를 사용한다.
