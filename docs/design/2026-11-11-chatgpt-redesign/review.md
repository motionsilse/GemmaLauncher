# ChatGPT 연결 재설계 검토 기록

작성: 2026-11-11. 대상: [설계서](design.md), [동작 시안](prototype.html).

> 후속 작업: 아래는 구현 전 시안의 검토 이력이다. 이후 0.4.3에 실제 화면과 동작을 적용했다. 현재 구현 결과·네이티브 검사·미검증 범위는 [구현 검증 기록](../../reviews/2026-11-11-chatgpt-redesign-implementation.md)을 따른다.

## 판단과 범위

이 문서는 설계와 HTML 시안에 대한 순차 자체 검토다. 독립 리뷰어 검토, 사용자 승인, 실제 앱 적용 완료를 뜻하지 않는다. 현재 앱의 UX가 통과했다는 이전 판단은 철회한다. 기능 테스트가 통과해도 로그인·로그아웃을 찾기 어렵고 서버 동작을 이해할 수 없다면 사용성 검증을 통과한 것이 아니다.

사용자가 지정한 변경 범위는 ChatGPT 연결 화면 전체와 공통 내비게이션이다. 로컬 모델 화면 내부는 시안에서도 범위 설명만 제공한다. 기존 로컬 모델 화면의 사용성이나 DPI 문제까지 이번 검토로 해결됐다고 주장하지 않는다.

## 발견한 문제와 설계 반영

| 기존 문제 | 새 설계 | 검토 결과 |
|---|---|---|
| 로그아웃이 접힌 진단 내부에 있음 | 계정 식별자 옆의 상시 동작으로 이동 | 넓은 창과 최소 크기 실행 상태에서 노출 확인 |
| 계정·서버·진단이 긴 세로 양식에 혼재 | 계정 영역과 API 서버 영역으로 분리 | 두 영역의 상태와 동작을 함께 확인 가능 |
| 로그인과 서버 실행이 같은 주 버튼에 섞임 | 로그인과 서버 켜기를 별도 명령으로 정의 | 시안에서 로그인 완료 후 서버가 꺼져 있음 |
| 서버 중지와 로그아웃 결과가 불분명 | 로그인 유지 안내와 로그아웃 확인문 제공 | 중지 후 계정 유지, 로그아웃 확인 후 첫 사용 상태 확인 |
| 로그인 전에도 사용 불가능한 연결값 노출 | 첫 사용 안내를 표시하고 준비 완료 후 연결값 제공 | 시안 첫 사용/실행 중 화면 확인 |
| 탐색과 실행 버튼의 형태가 같음 | 상단 텍스트 탐색·선택 밑줄, 영역별 동작 버튼 | 화면 이동 시 서버 상태 유지 확인 |
| 좁은 창에서 중요 동작이 밀림 | 계정 요약 행과 별도 사용량 보기, 고정 하단 상태 | 720×560 실행 상태에서 로그아웃·서버 끄기 가시성 확인 |

## 실제로 수행한 시안 검사

브라우저에서 예시 상태와 예시 계정으로 수행했다. 로그인·다운로드·추론·클립보드 변경은 발생하지 않는다.

- 1040×840에서 첫 사용, 브라우저 인증 대기, 저장된 계정/서버 꺼짐, 서버 실행, 사용량, 로그아웃 확인 화면을 열고 캡처했다.
- 로그인 대기 중 로컬 모델 탭으로 이동해도 공통 하단에서 로그인 취소가 가능함을 확인했다. 취소 후 ChatGPT 화면은 처음 사용 상태로 돌아왔다.
- 로그인 완료 재현 → 서버 꺼짐 → 별도 서버 켜기 → 실행 중 전환을 확인했다.
- 예시 API 키를 표시한 뒤 로컬 모델 탭과 ChatGPT 탭을 오가면 다시 마스킹됨을 확인했다.
- 서버 끄기 후 로그아웃 버튼이 남는 것을 확인했다. 로그아웃 확인창에서 취소하면 상태가 유지되고, 최종 확인하면 로그인 화면으로 돌아왔다.
- 720×560 실행 상태에서 실제 DOM 사각형을 검사했다. 로그아웃은 y=176–218, 본문 서버 끄기는 y=303–345, 공통 하단 서버 끄기는 y=522–550으로 뷰포트 안에 있었다.
- 포트 충돌 시 8319 포트의 사용 충돌 설명을 확인하고 캡처했다. 계정 읽기 실패 상태에서 서버 켜기 버튼이 노출되지 않는 것을 확인했다.
- 마지막 정상 탭에서 첫 사용 화면과 검토 도구의 노출을 다시 확인했다.
- 시안의 JavaScript 구문 검사와 변경 파일의 공백 오류 검사를 수행했다.

시안 검토 중 숨김 속성이 버튼 CSS에 의해 무효화되는 문제를 수정했다. 작은 창에서 계정 설명의 줄바꿈을 제거할 때 단어가 붙는 문제와 주요 상태 전환 후 포커스를 잃는 문제도 수정했다. 작은 창 실행 화면 캡처는 설명 공백의 마지막 수정 직전이며 레이아웃은 동일하다. 모든 키보드 이동·대화상자 포커스 경로를 완전 검사한 것은 아니다.

캡처의 계정·플랜·모델·사용량·키는 예시다. HTML 뷰포트 크기는 Windows 네이티브 창 크기나 물리 DPI 검증 결과가 아니다.

검토 중 내장 브라우저의 일부 로컬 페이지 재탐색이 `ERR_CONNECTION_RESET`으로 실패했다. 새 검토 탭에서는 정상 첫 사용 화면을 확인했다. 이 때문에 좁은 창의 첫 사용·로그인 대기 캡처 검사를 끝까지 수행하지 못했다. 실패한 탐색을 통과로 기록하지 않는다.

## 실제 앱 적용 전 남은 필수 검증

1. 현재 로그인 경로가 인증과 API 시작을 결합하므로, 인증 전용 수명과 명시적 서버 시작으로 분리해야 한다. 화면 문구 변경만으로 구현 완료 처리할 수 없다.
2. WinForms의 실제 클라이언트 영역에서 기본/최소 창과 100%·150%·200% DPI를 검사해야 한다. 작은 창의 첫 사용·로그인 대기·오류·긴 번역도 포함한다.
3. 17개 언어의 문구·레이아웃과 키보드 전용 조작, 대화상자 포커스 복귀를 검증해야 한다.
4. 버튼에서 시작하는 실제 엔진 다운로드·취소·실패, 브라우저 인증·재열기·취소·시간 초과를 검사해야 한다.
5. 실제 계정 로그인과 다른 클라이언트의 모델 조회·추론 성공은 별도 검증해야 한다. 이번 시안 검토에는 포함하지 않았다.
6. 포트 충돌·오래된 작업 완료·중지/로그아웃 정리 실패·동시 실행·트레이/완전 종료에서도 실제 상태와 설명이 일치해야 한다.
7. 사용자가 화면만 보고 로그인, 서버 켜기, 연결값 입력, 서버 끄기, 로그아웃을 구분할 수 있는지 검토해야 한다.

현재 결과는 기존 실패 지점을 구체적인 화면과 동작으로 바꾼 제안이다. 구현 기능 검증과 사용자의 디자인 판단이 남아 있다.
