# GemmaLauncher 재설계 리뷰

2026-11-10 · 최초 결론: **구현 기준으로 확정하기 전에 수정 필요**

후속 상태: 사용자 진행 지시에 따라 **R1–R5를 설계 문서와 시안에 반영했다.** 아래 발견 내용은 최초 리뷰 기록으로 보존하며, 끝의 반영 결과에서 현재 상태와 검증 범위를 확인할 수 있다.

검토 대상은 `DESIGN.md`, `docs/plans/2026-11-10-002-launcher-redesign.md`, 대화용 `gemma-launcher-redesign.html`이다. 배포된 v0.2.0이나 중단 전 WinForms 코드 전체에 대한 코드 리뷰가 아니다.

사용자 AGENTS 규칙에 따라 서브에이전트 없이 일관성·실행 흐름·제품 목적·구현 가능성·보안·범위를 순서대로 검토했다. 설계 문서는 요구사항 문서로 분류하고, 연계 계획은 구현 순서를 확인하는 데 사용했다. 보고 전용으로 진행했으며 검토 대상 파일에는 수정하지 않았다.

## 수정 제안

### R1 · P1 · 편집 화면에서 실행 제어가 사라진다

- 위치: `DESIGN.md:110`, 시안 HTML `:28`, `:52`, `:92`, `:98`.
- 근거: 중지/취소 버튼은 `.gl-home` 안에 하나만 있다. 편집 화면 진입은 `.gl-home`을 숨긴다. 실행 중에는 편집 진입이 허용된다. 공통 푸터에는 실행 제어가 없다.
- 재현 흐름: HY-MT2 1.8B 실행 → 프롬프트 편집 → 지시문 수정 → 모델을 중지하려고 함. 런처로 나가면서 저장 여부까지 결정해야 중지 버튼에 접근할 수 있다.
- 영향: 가장 중요한 서버 제어가 편집 작업에 종속된다. 설정을 만지는 동안 서버가 계속 자원을 사용하고 있어도 바로 멈출 수 없다.
- 제안: 실행 중에는 모든 작업 화면에 현재 모델·실행 상태·중지 동작을 작은 공통 영역으로 유지한다. 준비 중 보조 창을 열 수 있다면 취소 동작도 접근 가능해야 한다. 중지는 편집 초안의 저장/폐기와 독립적으로 동작한다.
- 분류: UX 설계 누락, 확신 100. 배치 방식은 판단이 필요하므로 문서 자동 수정 대상이 아니다.

### R2 · P2 · 공유 프롬프트의 변경 범위를 시안이 잘못 안내한다

- 위치: `DESIGN.md:120`, 시안 HTML `:52`, `:118`.
- 근거: 문서는 다른 모델도 쓰는 묶음이면 영향받는 모델 수를 표시하고 복제를 제공한다고 명시한다. 시안의 저장 안내는 항상 `선택한 모델의 다음 요청부터 적용됩니다`이며 복제 동작이 없다. 실제 시안 데이터는 공유 `presets[key]`를 덮어쓴다.
- 재현 흐름: E2B와 HY-MT2에 같은 기본 번역 설정을 적용 → E2B에서 설정 편집·저장. HY-MT2가 참조하는 지시문도 바뀌지만 저장 화면은 현재 모델만 안내한다.
- 영향: 사용자가 의도하지 않은 다른 모델의 번역 지침까지 바꿀 수 있다. 문서와 시안이 서로 다른 제품 동작을 검토받게 된다.
- 제안: 공유되는 경우에만 실제 사용 모델 수와 이름을 보여주고 `복제해서 현재 모델에 적용` 경로를 제공한다. 적용 모델이 하나면 안내를 늘리지 않는다.
- 분류: 문서/시안 불일치, 확신 100. 의미 있는 동작 추가이므로 수정 제안으로 남긴다.

### R3 · P2 · 새 설정을 버려도 저장 목록에 남는다

- 위치: 시안 HTML `:130`, `:133`; 요구사항 `DESIGN.md:117`.
- 근거: `새로 만들기`가 저장 전에 `presets`와 선택 목록에 항목을 추가한다. `버리기`는 `dirty`만 지우고 이동하며 새 항목을 제거하지 않는다.
- 재현 흐름: 새로 만들기 → 이름/지시문 편집 → 취소 → 버리기 → 다시 편집 화면 진입. 버린 `새 설정`이 남는다. 편집 시 입력한 이름과 지시문은 버려져 빈 항목이 누적될 수 있다.
- 확인: 생성 핸들러를 분리한 Node 실행 후 버리기 경로의 상태 변경을 적용했을 때 `presetsRemaining: 1`, `selectorOptionsRemaining: 1`이었다.
- 제안: 신규 항목은 편집 초안에만 두고 저장 성공 시 목록에 추가한다. 버리기는 신규 초안까지 폐기한다. 수정 중인 기존 항목에는 같은 삭제 처리를 적용하지 않는다.
- 분류: 시안 상태 관리 오류, 확신 100. 제품 구현에서는 회귀 테스트가 필요하다.

### R4 · P2 · 사용하지 않는 설정을 삭제해도 현재 설정이 해제된다

- 위치: 시안 HTML `:132`; 요구사항 `DESIGN.md:121`.
- 근거: 삭제 핸들러는 현재 모델이 삭제 대상 설정을 쓰는지 확인하지 않고 항상 `state.preset='none'`으로 바꾼다. 반면 `assigned`는 삭제 대상을 참조하는 항목만 바꾸므로 화면과 저장된 연결도 불일치한다.
- 재현 흐름: 현재 E2B는 `자유로운 글쓰기` 사용 → 편집 화면에서 `기본 번역`을 골라 삭제 → 메인에 돌아오면 현재 설정이 사용 안 함으로 바뀐다. 모델을 다시 선택하면 기존 할당이 되살아난다.
- 확인: 삭제 핸들러의 분리 실행 결과 `expectedCurrentPreset: creative`, `actualCurrentPreset: none`, `storedAssignment: creative`였다.
- 제안: 삭제 대상을 참조하는 모델만 기본값으로 돌린다. 현재 선택값은 변경 후 해당 모델의 실제 할당으로 다시 읽는다.
- 분류: 시안 상태 관리 오류, 확신 100. 현재 제품에 이 버그가 있다는 주장은 아니다.

### R5 · P2 · 실패 상황의 복구 화면이 아직 결정되지 않았다

- 위치: `DESIGN.md:98`, `:177`, 시안 HTML `:79`, `:102`, `:110`.
- 근거: 문서는 실패 동작을 `다시 시도 또는 해당 복구 동작`으로 남긴다. 사례 목록은 있으나 어떤 오류에서 무엇을 표시·변경할지 정하지 않았다. 시안의 상태에는 idle/download/loading/running만 있고 실패·중지 중을 검토할 수 없다.
- 영향: 권한이 없는 경우, 파일이 이동한 경우, 메모리가 부족한 경우에 모두 같은 재시도를 구현할 가능성이 있다. 복구하지 않은 원인으로 다시 실패하는 UI가 된다.
- 제안: 같은 실행 영역 안에 최소한 다운로드 실패/권한 필요/로컬 파일 이동/메모리 부족/포트 충돌의 원인 문구와 다음 동작을 대응시킨다. 예를 들어 권한 필요는 권한 연결, 파일 이동은 다시 연결, 메모리 부족은 지원되는 실행 설정 조정으로 이어진다. 중지 중에는 완료 전에 다시 시작하지 못하는 모습도 시안에 추가한다.
- 분류: 상태/복구 UX 누락, 확신 75. 오류별 동작에는 제품 판단이 필요하다.
