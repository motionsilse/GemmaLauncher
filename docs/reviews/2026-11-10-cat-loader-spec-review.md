# Cat Loader 설계 자체 검토

AGENTS.md의 순차 작업 규칙에 따라 작성자가 범위·일관성·실현 가능성·인증·데이터 보존을 각각 검토했다. 기준은 `docs/superpowers/specs/2026-11-10-cat-loader-integration-design.md`다.

- 두 기능과 두 주소를 합치지 않는다는 원칙을 확인했다. 카테고리 이동은 실행 명령이 아니며, 연결 테스트와 사용량 조회를 구분했다.
- CatRoute의 현재 제품은 WinForms다. 과거 WPF 검증 문서를 근거로 UI 재작성 범위를 잘못 잡지 않았다. 제품용 core와 필요한 저장 도우미로 이관 범위를 한정했다.
- 가벼운 시작과 기존 CatRoute의 자동 연결은 충돌한다. 통합 앱은 명시적 연결 버튼을 기준으로 정하고, 기존 자동 연결을 묵시적으로 실행하지 않도록 명시했다.
- 새 이름과 데이터 보존의 충돌을 해소했다. 기존 데이터 폴더·DPAPI entropy·API 키·중복 실행 잠금은 호환성 대상으로 유지한다.
- 트레이로 숨기기와 CatRoute의 기존 창 닫기 종료가 다르다. 공통 설정을 기준으로 두 기능에 적용하고, 첫 통합 안내와 설정에서 설명하도록 명시했다.
- 별도 카테고리와 전역 중지의 충돌을 확인했다. 실행 중인 두 기능은 다른 화면과 대화상자에서도 구분해서 제어할 수 있어야 한다.
- 프록시 엔진 비내장은 파일 크기 개선 근거다. 실행 중 RAM·CPU 감소는 측정 전 확정하지 않는다. 기존 엔진 재사용·추가 다운로드 취소·부분 실패를 검사에 포함했다.
- 실제 사용자 토큰·연구 바이너리·원본 작업공간을 통합 빌드나 테스트 의존성으로 사용하지 않도록 명시했다.
- 공개 이행 전에 저장소를 삭제하거나 보관하지 않는다. 구현 산출물과 공개 이행을 구분했다.
- 미정 표식과 상충하는 주소·버전·파일 해시는 없다. 신규 기능은 실행 계획 작성과 구현 전 문서 검토 단계다.

결론: 사용자 검토에 제출할 수 있다. 작성된 설계서와 이후 구현 계획의 사용자 검토 전에는 제품 코드를 수정하지 않는다.
