# ANIS 실계정 통합 검증과 0.1.0 수정 재배포

2026-11-11 · 순차 자체 리뷰. 사용자의 컴퓨터 유즈 금지 요청 후 화면 자동조작 도구를 사용하지 않았다.

## 발견한 결함과 원인

실제 Hugging Face OAuth 서버가 HTTP 200으로 인증 값을 발급했는데 Cat Loader는 로그인 실패로 처리했다. 진단 시 값 자체를 기록하지 않고 길이 573과 구분 문자 `.`(코드 46)만 확인했다. `HuggingFaceAuthorization`이 영문·숫자·`_`·`-`만 허용해 정상적인 인증 값을 거부했으며 `AnisBackend`의 다운로드 검사에도 같은 오류가 있었다.

두 곳에서 [RFC 6750 §2.1](https://www.rfc-editor.org/rfc/rfc6750.html#section-2.1)의 Bearer 문법을 공유하도록 수정했다. `.`을 포함한 허용 문자를 처리하되 공백·줄바꿈·비ASCII·중간 padding·빈 값·4096자를 초과하는 값은 거부한다. 인증 값은 불투명한 자격 증명으로 전달하며 내용이나 서명을 앱에서 해석하지 않는다. 기존 헤더 전송·PKCE·state 검사·외부 CDN으로의 인증 헤더 차단은 유지한다.

이전 모의 응답은 `hf_oauth_fixture`만 사용해 실제 인증 형식의 차이를 놓쳤다. 점으로 구분된 모의 응답으로 수정 전 동일한 실패를 확인하고, 수정 후 인증 재사용 및 다운로드 리디렉션 회귀 검사까지 통과시켰다. 서버가 정상 응답했다는 것과 앱에서 해당 응답을 처리할 수 있다는 것을 따로 검증해야 했다.

## 실계정 실행 조건

- 기존 브라우저 로그인 세션을 이용해 공식 Hugging Face OAuth와 실제 로컬 콜백·코드 교환을 실행했다. 브라우저 조작, 쿠키 추출, 비밀번호 입력 자동화, 인증 값 로그·파일 저장은 하지 않았다.
- 새로 만든 비어 있는 테스트 디렉터리에 공식 모델 파일 네 개를 전부 네트워크로 받았다. 기존 모델 경로나 Downloads 가져오기를 사용하지 않았다.
- 원본 Hugging Face 요청에만 인증 헤더가 있었으며 `us.aws.cdn.hf.co` 리디렉션 요청에는 없었다. 파일 크기·고정 해시를 검사했고 새 backend 인스턴스로 디스크 파일을 다시 검증했다.
- 공식 소스·전용 Python·CTranslate2 환경도 새로 설치했다. 앱과 같은 `EnableGateway=true`, 빈 프리셋, `AnisDevice=auto`, `anis-trans:auto` 설정으로 실행했다.
- 최초 테스트 작성 시 공용 API 중계를 빠뜨려 직접 ANIS 요청이 400을 반환했다. 실제 앱은 중계를 켜므로 제품 결함으로 분류하지 않고 테스트 설정을 앱과 맞춘 뒤, 새로운 빈 디렉터리에서 전 과정을 재실행했다.
- CUDA 라이브러리를 사용할 수 없는 이 PC에서는 공식 프로그램이 CPU INT8로 전환했다. GPU 경로의 성공을 주장하지 않는다.

## 회귀 검사와 재현

Release 빌드(경고 0·오류 0), Core 전체, 17개 언어·508개 키, 카탈로그 동기화, diff 검사를 통과했다. 인증·다운로드 검사 두 곳을 다시 검토해 동일한 검증 함수를 쓰는지 확인했다. 배포 전 단일 EXE 검증과 업로드 후 다운로드 해시 검증을 수행한다.

```powershell
dotnet build GemmaLauncher.sln -c Release
dotnet run --no-build --project tests/GemmaLauncher.Tests -c Release
# 아래 디렉터리는 아직 존재하지 않아야 한다. 실제 로그인과 약 1 GB의 임시 공간이 필요하다.
dotnet run --no-build --project tests/GemmaLauncher.Tests -c Release -- --anis-live-smoke D:/TestData/anis-new-install
```

실계정 검사는 명시적으로 실행하는 선택 테스트다. 일반 테스트 실행에서 브라우저를 열거나 모델을 받지 않는다. 최종 통합 실행 원자료는 [report.json](assets/0.1.0/anis-live-report.json)에 보관한다.

0.1.0의 EXE·체크섬·릴리즈 설명과 소스 태그를 수정 커밋에 맞춰 교체한다. 버전 번호가 같아 기존 설치의 업데이트 알림이 뜨지 않으므로 재다운로드가 필요하다.
