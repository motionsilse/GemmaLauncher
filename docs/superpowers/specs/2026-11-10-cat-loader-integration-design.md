# Cat Loader 통합 설계

상태: 설계서 승인 · 2026-11-10 사용자 선택 1 · 구현 계획 검토 단계

기준: GemmaLauncher `da4cd94`, CatRoute `c5c74ad` · 2026-11-10

## 목적과 제품 범위

Cat Loader 하나에서 로컬 모델 실행과 ChatGPT 계정 연결을 제공한다. 두 기능의 공통 목적은 다른 앱이 사용할 OpenAI 호환 연결을 준비하는 것이다. 사용자는 실행 위치, 필요한 자원, 연결 상태와 사용할 주소를 구분할 수 있어야 한다.

이번 설계는 사용자가 진행을 승인한 방향을 구체화한다. 실제 앱 이름은 `Cat Loader`, 배포 파일은 `CatLoader-0.4.0-win-x64.exe`를 제안한다. 내부 네임스페이스·모델 ID·기존 저장 경로는 호환성을 위해 유지할 수 있다. 제품을 실행하는 데 원본 CatRoute 작업공간이 필요해서는 안 된다.

| 상단 카테고리 | 제공 기능 | 기존 연결 주소 |
|---|---|---|
| 로컬 모델 | 기본 모델 6개, 사용자 GGUF, 준비·실행·중지, 프롬프트·용어사전 | `http://127.0.0.1:8080/v1` |
| ChatGPT 연결 | 로그인·로그아웃, 연결·중지, 연결 정보 복사, 모델 확인, 사용량 조회·연결 테스트 | `http://127.0.0.1:8319/v1` |

자동 소스 전환, 두 서버를 합친 단일 주소, 사용량 초과 시 로컬 모델로 자동 대체, 새 채팅·번역 GUI는 이번 범위에 넣지 않는다. 기존 ANIS 출처·접근 권한 흐름도 유지한다.

## 확인한 기존 구조와 선택

- 두 앱의 현재 UI는 모두 WinForms다. GemmaLauncher는 .NET 10, CatRoute 제품 앱은 .NET 8을 대상으로 한다. 과거 WPF 실험과 현재 제품 코드를 혼동하지 않는다.
- CatRoute 제품 기능은 `CatRoute.CodexProxy.Core`의 로그인·프로세스·모델·사용량 코드와 일부 저장 도우미를 사용한다. `MainForm`에는 UI 상태 처리도 들어 있어 그대로 별도 창으로 실행하는 방식보다 기능 서비스와 새 페이지로 옮기는 방식이 적합하다.
- CatRoute는 CLIProxyAPI를 gzip 리소스로 포함한다. 확인한 압축 엔진은 23,584,608바이트, 실행 파일은 72,386,560바이트다. UI 통합에 더해 이 배포 방식을 바꿔야 작은 EXE를 유지할 수 있다. 실행 중 엔진의 메모리는 별도 측정 대상이다.

선택한 방식은 기존 런처를 공통 창으로 확장하고 CatRoute의 제품용 핵심 기능을 편입하는 것이다. 두 EXE를 메뉴로 묶으면 창·트레이·설정과 기동 비용이 중복된다. 처음부터 API까지 하나로 합치면 기존 주소·키·요청 처리의 의미가 바뀌므로 현재 두 주소를 보존한다.

## 화면과 문구

상단은 `Cat Loader` 제목, `로컬 모델`·`ChatGPT 연결` 전환, 공통 `설정`으로 구성한다. 기존 로컬 모델 화면과 넓은 프리셋 편집기를 유지한다. 기능 전환 자체는 다운로드·로그인·연결·종료를 수행하지 않는다.

ChatGPT 연결 화면은 다음 순서로 구성한다.

1. **역할 안내:** `ChatGPT 계정을 다른 앱에 연결합니다. 인터넷 연결이 필요하며 계정의 사용량 한도를 함께 사용합니다.`
2. **계정과 상태:** 로그인 필요, 저장된 계정, 연결 중, 연결 가능, 중지, 확인 필요를 구분한다. 로그인돼 있다는 사실과 로컬 API가 연결 가능하다는 사실을 별도 표시한다.
3. **주 동작:** 계정이 없으면 `ChatGPT 로그인`, 저장된 계정이 있으면 `연결 시작`, 준비 중이면 `작업 취소`, 연결 중이면 `ChatGPT 연결 중지`를 사용한다.
4. **앱 연결:** API 주소, 기본 마스킹된 로컬 API 키, 실제 API 모델 이름과 각각의 복사 버튼. `연결 정보 모두 복사`도 제공한다. OAuth 토큰은 표시·복사하지 않는다.
5. **계정 관리:** `사용량 조회`, `연결 정보 새로고침`, `로그아웃`을 구분한다. 로그아웃에는 이 PC에 저장한 로그인을 지우며 원격 계정 권한 취소는 아니라는 설명을 둔다.
6. **연결 테스트:** `실제 요청으로 연결 테스트`라고 표시하고, 버튼 앞에 실제 요청 1회를 보내며 계정 사용량에 반영될 수 있음을 안내한다. 사용량 조회와 모델 조회는 추론 테스트로 대체하지 않는다.

로컬 영역에는 `이 PC에서 모델을 실행합니다. 모델 파일과 RAM·VRAM이 필요합니다.`라는 구분을 제공한다. 공통 바닥글이 ChatGPT 연결까지 오프라인 실행인 것처럼 설명해서는 안 된다. 새 핵심 문구와 조작은 기존 17개 언어에 반영하고 계정·모델·플랜의 서비스 제공 이름은 원문을 유지한다.

기능 이동 시 다른 영역의 서버가 살아 있으면 기능 이름·상태·중지/취소 버튼을 고정 영역에서 보여준다. 보조 화면·공통 설정·초안 확인 대화상자 안에서도 실행 중인 두 기능을 각각 중지할 수 있어야 한다.

## 실행 수명과 가벼운 시작

- 창·트레이·표시 언어·공통 설정은 하나다. 기능별 서비스와 취소 상태는 독립적이다. 로컬 모델 하나와 ChatGPT 연결을 동시에 사용할 수 있다.
- 프로그램을 열거나 카테고리를 바꾸기만 해서는 모델 또는 프록시 엔진을 실행하거나 외부 서비스에 추론을 요청하지 않는다. 첫 활성화 때 필요한 화면·서비스만 만든다. 사용하지 않는 영역의 모델 파일 전체 검증이나 계정 엔진 준비가 초기 화면을 지연시키지 않게 한다.
- ChatGPT 카테고리를 처음 열면 저장된 계정 상태를 읽을 수 있으나 엔진 준비·브라우저 로그인·서버 시작은 명시적 버튼으로 시작한다. 기존 자동 연결 행동은 묵시적으로 옮기지 않는다.
- 카테고리 이동과 화면 닫기는 서비스 폐기 동작이 아니다. 로그인·준비 취소는 해당 기능의 작업만 취소한다. 한쪽 오류로 다른 서버를 종료하지 않는다.
- 창 닫기는 현재 런처의 `트레이에서 계속 실행` 설정을 따른다. 첫 통합 실행의 안내와 설정에서 두 기능에 적용된다는 점을 설명한다. 완전 종료는 두 기능의 작업을 취소하고 소유한 프로세스를 정리한 뒤 창·트레이를 닫는다.
- 트레이 항목은 `로컬 모델 …`, `ChatGPT 연결 …`, `Cat Loader 열기`, `완전 종료`로 대상을 명시한다. 현재 카테고리에 따라 의미가 바뀌는 범용 ‘실행’ 항목은 두지 않는다.

## 기존 데이터와 실행 충돌

| 데이터 | 처리 |
|---|---|
| GemmaLauncher의 모델·캐시·사용자 모델·프리셋 | 기존 기본 데이터 폴더와 저장 형식을 보존한다. 이름 변경만으로 모델을 다시 받지 않는다. |
| CatRoute 계정과 로컬 API 키 | 기존 `CatRouteCodexProxy` 저장 폴더를 사용한다. 실제 사용자 토큰을 복사하거나 변환하는 마이그레이션은 하지 않는다. |
| DPAPI 보호 데이터 | 현재 사용자 범위와 기존 entropy 식별자를 보존한다. 제품명 변경을 암호화 식별자 변경으로 연결하지 않는다. |
| 표시 언어 | 기존 런처 설정이 있으면 우선한다. 런처 설정이 없는 경우에만 CatRoute의 `ui-language.json`에 저장된 auto/ko/en을 가져오고 이후 공통 설정으로 관리한다. |
| 최근 화면 | 기능 구분만 저장한다. 복원 시 서버나 로그인을 자동 실행하지 않는다. |

기존 GemmaLauncher와의 사용자별 중복 실행 방지·활성화 신호를 보존한다. CatRoute가 기존 저장 폴더를 사용 중이면 그 소유권 잠금을 존중하고 `기존 CatRoute를 종료한 뒤 다시 연결하세요`로 안내한다. 다른 프로그램의 프로세스를 찾아 강제로 종료하거나 인증 파일을 덮어쓰지 않는다. 로그인 파일이 손상됐거나 여러 계정이 있으면 이를 구분하고 자동 삭제·자동 계정 전환을 하지 않는다.

## ChatGPT 엔진 준비와 코드 이관

CLIProxyAPI v8.0.27의 공식 Windows amd64 ZIP을 첫 연결 준비 시 다운로드한다. 기존 엔진이 올바른 해시라면 재사용한다. 다운로드·검증·압축 해제 단계는 취소 가능하며 손상된 엔진의 복구가 계정 파일 삭제로 이어져서는 안 된다.

- ZIP SHA-256: `ac6867818696aefe299c8bac1730f831cbb127f0854acca1b1aebb0110a5dc53`
- EXE SHA-256: `a3620a7e8d54d0f4257b493ea5fc01b3c59d581fb8c3596df5880976596da162`
- 원본: `https://github.com/router-for-me/CLIProxyAPI/releases/download/v8.0.27/CLIProxyAPI_8.0.27_windows_amd64.zip`

엔진은 수정하지 않고 원본 라이선스·출처를 보존한다. 자동 엔진 업데이트는 추가하지 않는다. Cat Loader EXE에 엔진·모델·.NET 런타임을 넣지 않는다. 시스템 .NET 10 Desktop·ASP.NET Core 런타임을 공통으로 사용한다.

CatRoute `c5c74ad`의 제품용 `CliProxyHost`, `CodexLogin`, `ProxyApi`, `UsageApi`, `OwnedProcess`와 필요한 키·잠금·저장 처리를 선별해 이관한다. 원본 작업공간에 대한 project reference나 절대 경로 의존성을 만들지 않는다. `research/`, `.local/`, CatBridge 소스·연구 DLL, 이전 직접 인증 실험 전체와 압축 엔진 payload 프로젝트는 가져오지 않는다. 출처와 변경 내역을 남긴다.

## API와 인증 계약

두 주소·모델 식별자·기존 로컬 API 키를 보존한다. CatRoute가 현재 지원하는 모델 확인과 요청 중계 동작을 유지하며 사용 불가능한 기본 모델을 임의의 다른 모델로 대체하지 않는다. 프롬프트·용어사전은 로컬 모델 영역의 명시적 설정으로 유지하고 ChatGPT 요청에 자동 주입하지 않는다.

계정 연결은 기존 검증된 시스템 브라우저·state·루프백 callback 흐름을 유지한다. 비밀번호·패스키·동의는 사용자가 수행한다. 브라우저에서 callback을 받았다는 사실만으로 로그인 완료라고 표시하지 않고 엔진에 저장된 계정과 API 준비를 각각 확인한다. 로그·알림·예외·패키지에 키·토큰·인증 코드·요청 본문을 남기지 않는다.

사용량 조회 오류는 연결 자체의 실패로 단정하지 않는다. 제공되지 않은 한도·초기화 시각은 추정하지 않는다. 숫자·시간은 서비스 응답과 PC 현지 시각을 사용한다. 일반 오류 안내에는 어느 기능의 어떤 작업이 실패했는지 표시하고 재시도 버튼은 실제 그 작업만 반복한다.

## 검증과 완료 기준

1. 빈 테스트 데이터 폴더에서 시작·카테고리 전환만 수행했을 때 엔진 자식 프로세스와 외부 네트워크 요청이 모두 0이다.
2. 로컬의 기본 6개 모델 노출·준비·실행·중지·사용자 GGUF·프리셋 회귀 검사가 통과한다. 계정 연결 범주를 열어도 선택 모델과 연결 주소가 바뀌지 않는다.
3. 독립된 가짜 서버/호스트로 두 기능 동시 실행, 한쪽 취소·충돌·오류, 다른 영역 이동, 숨기기·복원·완전 종료를 검증한다. 종료 후 소유한 프로세스와 listener가 남지 않는다.
4. 기존 CatRoute 형식의 가짜 데이터로 로컬 API 키 유지와 파일 잠금·ACL·손상 상태 처리를 검증한다. 실제 사용자 데이터와 자격 증명은 테스트에서 읽거나 삭제하지 않는다.
5. 공식 엔진의 최초 다운로드·재사용·손상 복구·취소·무결성 거부를 검증한다. 실제 브라우저 인증과 upstream 추론 검증 여부는 mock/로컬 프로토콜 검사와 분리해 기록한다.
6. 로그인 취소·기한 만료·callback 포트 충돌·사용량 조회 실패·한도 누락·준비 도중 종료를 검증한다. 연결 테스트만 실제 추론 요청을 수행한다.
7. 네이티브 화면에서 새 계정 화면, 기존 계정, 준비 중, 연결 가능, 오류, 두 기능 동시 동작, 작은 창, 미저장 초안 대화상자와 17개 언어를 확인한다.
8. 최종 단일 EXE를 비어 있는 폴더에서 검증한다. 엔진·모델 비내장을 확인하며, 초기 배포 파일은 5MiB 이하를 목표로 한다. 콜드 시작과 유휴 RAM·CPU는 기존 런처와 동일 조건으로 측정해 차이를 기록한다. 엔진 메모리까지 줄었다고 추정해 보고하지 않는다.
9. 새 이름·두 기능 설명·출처·보존된 데이터 경로·업데이트 방법을 README와 내장 고지에 반영한다. 패키지·기존 모델·계정 기능 회귀가 통과해야 통합 배포 후보로 표시한다.

## 배포와 저장소 이행

이번 설계의 구현 산출물은 검토 가능한 로컬 통합 앱·테스트·패키지다. 공개 저장소 이름 변경과 배포, CatRoute 보관은 동작 확인과 이행 안내 이후의 단계로 분리한다. 통합 앱이 배포되기 전에 기존 CatRoute 릴리즈나 저장소를 제거하지 않는다. 권장 이행은 통합 버전 배포 → 기존 사용자 안내·이전 확인 → CatRoute 읽기 전용 보관이다. 저장소 삭제는 이 설계의 작업에 포함하지 않는다.

## 구현 계획으로 넘길 단위

1. 선택적 다운로드와 기존 저장소 호환을 갖춘 계정 연결 서비스·프로토콜 검사.
2. 두 카테고리, 계정 화면, 공통 수명·알림·트레이와 UI 검사.
3. Cat Loader 브랜딩·고지·문서·성능 측정·최종 패키지 검증.

위 단위는 실행 계획의 순서이며 아직 제품 코드 변경이나 문서 승인 후 작성할 세부 구현 계획을 의미하지 않는다.
